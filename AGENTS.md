# BranchBlitz

Fast desktop git client in Rust (eframe/egui 0.37). Focus: see every local/remote branch + tag in the graph, merge via right-click.

**Be concise. Knowledge base, when present (local, not in the repo): `brain/` (read `brain/index.md` first, schema in `brain/CLAUDE.md`).**

## Working rules

- Simplicity first; surgical changes; match existing style. Every changed line traces to the request.
- Turn tasks into verifiable goals (bug → reproduce in a test → fix). Loop until verified.
- All git work goes through the `git` CLI in `src/git.rs` (`Op::run`). Never shell out elsewhere.
- UI code collects an `Action` while drawing and applies it after the frame; don't mutate state mid-draw.

## Layout

```
src/main.rs    viewport + run_native
src/app.rs     App state, tabs, worker threads, modals, toolbar, settings; ui tests at bottom
src/views.rs   sidebar, graph view, context menus, details/WIP/diff panels
src/git.rs     git CLI layer: load(), Op enum, diff; integration tests against temp repos
src/graph.rs   lane layout (pure, unit-tested)
src/theme.rs   design system tokens (Palette), themes, egui style
src/ds.rs      design system widgets: Button/split, chips, rows, menu items, search field

src/fonts.rs   bundled Inter / JetBrains Mono / Lucide + optional system fonts
assets/        fonts (OFL/ISC licences alongside), bolt.png
src/mcp.rs     `branchblitz mcp`: stdio MCP server driving the app headless (kittest harness)
src/agent.rs   agent panel conversation; backends: Claude Code (`claude -p` stream-json) and a preview
src/live.rs    the running app's own MCP endpoint (Unix socket) for its agent; `mcp --attach` bridge
src/conflict.rs  conflict-marker parsing and per-block resolution (pure, unit-tested)
scripts/demo-repo.sh   throwaway repo with origin, merges, tags, WIP (default /tmp/bbdemo)
```

## Run (Rust via mise: prefix with `mise exec --` if cargo is not on PATH)

```sh
cargo run -- /tmp/bbdemo/work
cargo install --path .        # ~/.local/bin/branchblitz symlinks to ~/.cargo/bin
BB_DEBUG_REPAINT=1 branchblitz   # stderr: frames per 2 s and why (an idle window should draw none)
```

## Verify work (all must pass)

```sh
cargo clippy --all-targets -- -D warnings
cargo test
scripts/demo-repo.sh && BB_DEMO=/tmp/bbdemo/work cargo test render -- --ignored --nocapture   # UI: /tmp/bb-*.png
```

Look at the rendered PNGs for any UI change.

## See the app (MCP)

`.mcp.json` registers `branchblitz` (`cargo run -- mcp`). Use it to check UI changes like a user: `demo_repo` →
`screenshot` → `widgets` → `click`/`type_text`/`key` → `wait_idle` → `screenshot`/`state`. The server runs the
build from when it started: after code changes, reconnect it (`/mcp`) before judging the result. Turn findings
into a test in `mcp::tests` or `render_tests`. Never point it at the user's real repos unless asked. The merge render test mutates the demo repo; rebuild it before rerunning.

## Anti-patterns (update when mistakes found)

- Don't use emoji or Unicode symbols as icons → use `icons::*` (Lucide); add new ones in `scripts/lucide-subset.sh`. Other glyphs must exist in the bundled fonts (`glyph_check` guards app.rs/views.rs/settings_view.rs/ds.rs; Inter has ↑↓…—·×, not →).
- Don't hard-code colours, sizes or radii in UI code → take them from `Palette` / `theme::RADIUS_*` / `ds::CONTROL_*`; the source is the BranchBlitz design system artifact (brain: [[design-system]]).
- Don't paint a widget without `widget_info` → the MCP server and kittest find widgets by accessible label; keep long descriptions (e.g. "Merge x into y") as the label when the visible text is shortened.
- Don't pass user/remote-controlled names to git without `Op::names()` guard → names starting with `-` become options.
- Don't rely on pathspec magic → `GIT_LITERAL_PATHSPECS=1` is set; paths are literal.
- Don't run network git without `git_network()` timeout; never let git prompt (`GIT_TERMINAL_PROMPT=0`, stdin null).
- Don't open a modal from async results with direct assignment → use `offer_modal` (won't clobber an open dialog); modals carry their tab id. Confirmations are not modals: `Action::Confirm` puts an `Alert` on the tab, shown as a bar under the toolbar.
- Don't `pkill -f target/debug/branchblitz` from a shell whose cmdline matches → kills itself.
- Don't screenshot the real window with grim while the laptop panel is off → hangs; use the MCP `screenshot` tool.
- Don't print to stdout outside tests → stdout is the MCP channel in `branchblitz mcp`.
- Don't add UI that needs a real window (dialogs, spawning apps) without a `headless` fallback.
- Don't push, merge or cherry-pick from a local `archive/*` branch → pre-publication history with names that must not go public; work on `main` only (brain: [[publishing]]).
- Don't commit before the tests pass → gate the commit on the test result, not on running them.
